# Transfer Node Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a first-class offline `TRANSFER` node that moves data between supported JDBC-style data sources through Apache SeaTunnel, while preserving the existing save, commit, push, Kestra scheduling, and Operations Center workflow.

**Architecture:** Treat WB-Data as the configuration and credential owner, Kestra as the scheduler and execution recorder, and SeaTunnel as the isolated transfer runtime. Git stores only non-secret transfer configuration under the offline Flow directory. Kestra runs transfer tasks as `io.kestra.plugin.scripts.shell.Commands` with the Kestra Docker task runner and a SeaTunnel container image. The SeaTunnel job configuration is rendered at execution time by a WB-Data internal backend endpoint so database passwords never land in Flow YAML or Git-managed transfer JSON.

**Tech Stack:** Spring Boot 3, Java 21, MyBatis-Plus, SnakeYAML, Jackson, React 18, TypeScript, Vite, Vitest, Testing Library, Apache SeaTunnel 2.3.x, Kestra Docker task runner, Docker Compose.

---

## Global Constraints

- V1 supports `MYSQL`, `POSTGRESQL`, `STARROCKS`, and `HIVE` data sources only.
- V1 supports batch transfers only.
- V1 excludes Elasticsearch, MongoDB, Kafka, files, CDC, automatic table creation, and cross-dialect expression translation.
- Git-managed files must not contain data source passwords, bearer tokens, or generated SeaTunnel runtime configs.
- The user enters source SQL predicate and expression fragments. The system adds `WHERE` and target aliases.
- Hive target partition status and partition columns are system-detected.
- Hive partitioned targets expose only `append` and `overwrite_partition`.
- Non-partitioned targets expose only `append` and `overwrite_table`.
- Existing `SQL`, `HIVE_SQL`, and `SHELL` node behavior must keep round-tripping through save, commit, push, debug execution, scheduled execution, and node editor reopen.
- Commit after each finished task, using one logical commit per task.

## Runtime Contract

Generated Kestra transfer task shape:

```yaml
id: transfer_node_1
type: io.kestra.plugin.scripts.shell.Commands
description: |
  [wbdata-meta] nodeKind=TRANSFER;transferConfigPath=transfers/example/transfer_node_1.transfer.json
namespaceFiles:
  enabled: true
  include:
    - transfers/example/transfer_node_1.transfer.json
containerImage: apache/seatunnel:2.3.13
taskRunner:
  type: io.kestra.plugin.scripts.runner.docker.Docker
  pullPolicy: IF_NOT_PRESENT
  networkMode: wb-data-integration
commands:
  - |
    set -euo pipefail
    mkdir -p /tmp/wb-data-transfer
    curl -fsS \
      -H "X-WB-Data-Internal-Token: ${WB_DATA_INTERNAL_TOKEN}" \
      -H "Content-Type: application/json" \
      --data-binary @transfers/example/transfer_node_1.transfer.json \
      "${WB_DATA_INTERNAL_BASE_URL}/api/v1/internal/offline/transfer/render" \
      > /tmp/wb-data-transfer/transfer_node_1.conf
    ./bin/seatunnel.sh --config /tmp/wb-data-transfer/transfer_node_1.conf -m local
```

Required Kestra environment:

- `WB_DATA_INTERNAL_BASE_URL`: backend URL reachable from the SeaTunnel task container.
- `WB_DATA_INTERNAL_TOKEN`: shared local/internal token configured in backend and Kestra.
- Docker socket access for Kestra Docker task runner in local integration mode.
- Docker network `wb-data-integration` shared by Kestra task containers, MySQL, Hive, and WB-Data backend.

SeaTunnel configuration rules:

- Source uses SeaTunnel JDBC source with `query = "select ... from ... where ..."` for all V1 source types.
- Non-Hive target uses SeaTunnel JDBC sink with `generate_sink_sql = true`, `schema_save_mode = "ERROR_WHEN_SCHEMA_NOT_EXIST"`, and `data_save_mode = "APPEND_DATA"` or `DROP_DATA`.
- Hive target uses Hive write SQL generated by WB-Data for V1 partition behavior. The rendered SeaTunnel job reads from JDBC/HiveJdbc source and writes to Hive through a generated Hive sink insert statement.
- Runtime smoke tests must verify connector names, Hive sink dependencies, and the SeaTunnel image tag before feature tasks depend on the runtime.
