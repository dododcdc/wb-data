# 离线调度配置重构设计文档 (Offline Scheduler Refactoring)

## 1. 概述 (Overview)
本项目旨在重构离线开发工作台中的“调度配置”模块，提升其视觉美感、交互确定性以及与整体草稿保存链路的一致性。

## 2. 核心变更 (Core Changes)

### 2.1 交互链路：从“即时保存”到“统一暂存”
*   **当前问题**：修改调度配置会立即调用 API 修改本地文件，与画布修改需要手动点击“保存”的逻辑不一致，容易造成误触。
*   **新设计**：
    1.  调度配置弹窗内的所有操作（Cron、时区、开关）均仅修改内存中的 `DraftSession`。
    2.  弹窗底部按钮更名为 **“暂存配置”**。
    3.  最终的持久化通过工作台顶部的全局 **“保存”** 按钮完成，实现“一次 Commit，完整变更”。

### 2.2 UI 布局与美化 (UI Layout & Aesthetics)
*   **分段式 Cron 输入**：将单一的 Cron 字符串输入框拆分为 5 个独立的 Input 框，下方标注中文“分、时、日、月、周”。
*   **默认值引导**：首次进入配置且无现有配置时，默认填充 `0 2 * * *` (每日凌晨 2 点)。
*   **调度预览强化**：展示未来 **5 次** 执行时间，并每一行均显式标注 **时区**（如 Asia/Shanghai）。
*   **独立开关控制**：将“启用调度状态”开关从右上角移至预览区下方，作为一个独立的决策模块，并增加状态解释说明。

## 3. 技术规格 (Technical Specs)

### 3.1 数据流 (Data Flow)
*   **前端状态**：在 `FlowDraftSession` 中增加 `scheduleDraft` 字段，存储临时的调度配置。
*   **YAML 同步**：点击“暂存配置”时，调用工具函数解析 Cron 段并回写到 `draftSession.workingDraft` 的 YAML 字符串中（`triggers` 部分）。
*   **时区处理**：继续使用 `Intl.supportedValuesOf('timeZone')` 获取时区列表，但在预览时需确保时区偏移量计算准确。

### 3.2 组件结构 (Component Structure)
*   **SegmentedCronInput**: 新增分段输入组件，支持自动焦点切换或手动 `Tab` 切换。
*   **SchedulePreview**: 增强型预览组件，支持 5 次时间计算及显式时区展示。
*   **ScheduleDialog**: 整合上述组件，并实现“暂存”逻辑。

## 4. 异常处理 (Error Handling)
*   **非法 Cron 校验**：若分段输入的内容无法组成合法 Cron，预览区显示“无效的表达式”，且“暂存配置”按钮禁用。
*   **时区冲突**：若 YAML 中的时区与当前系统不匹配，应以 YAML 记录为准。

## 5. 验收标准 (Acceptance Criteria)
*   [ ] 调度配置弹窗采用分段式输入。
*   [ ] 首次进入默认填充“每日凌晨 2 点”。
*   [ ] 预览区显示未来 5 次运行时间且带有时区标记。
*   [ ] 点击“暂存配置”后，画布上方保存按钮变为活跃状态，且不触发网络请求。
*   [ ] 点击全局保存后，本地 YAML 文件被正确更新。
