# 提案：离线画布草稿生命周期改造（去掉手动保存）

> 状态：**V1 已交付（2026-09-23）**；V1.1 / V2 待立项
> 缘起：CRM 端到端测试 P-04 / P-08 / P-09（[crm-e2e-scenario-test-plan.md](crm-e2e-scenario-test-plan.md) §9）及后续讨论
> 讨论结论（2026-09-20/22 已对齐）：取消手动「保存任务」；「提交」为唯一显式动作；「放弃修改」= 回退到最近一次保存的草稿；乐观锁不隔离；diff 展示后置

## 1. 背景：三连事故的根因

CRM 测试中抽数任务 5 节点配置全丢，因果链：

1. 「保存任务」需要手动点；且**保存会跑图校验**（节点必须连入一张图），校验失败只弹一个 toast——用户（和当时的我）极易错过，以为已保存。
2. 切换任务时「保存并离开」两次不生效（P-04，疑似执行状态回写反复弄脏草稿）。
3. 被迫「放弃修改」→ 回退到 git 已提交版本（空壳 flow.yaml），草稿全丢（P-08）。

根本问题：**「保存 / 提交」两层心智 + 保存可能静默失败 + 放弃语义指向错误的还原点**。

## 2. 现状机制摸底（重要：很多零件已经存在）

代码锚点：`wb-data-frontend/src/views/offline/useFlowEditingSession.ts`

| 能力 | 现状 | 锚点 |
|------|------|------|
| 服务端草稿 | 手动「保存任务」→ `saveOfflineFlowDocument` | `saveFlow` |
| 乐观锁（CAS） | **已有**：保存冲突 → `saveConflictState` 弹窗（覆盖/丢弃/取消） | `isSaveConflictError`、`overwriteSaveConflict` |
| 崩溃恢复 | **已有**：离开/异常时写 localStorage recovery snapshot，重开提示恢复 | `recoverySnapshotStore`、`leaveCurrentFlow` |
| 脏判定 | `isDirty = hasFlowDraftChanges(draftSession)`（工作草稿 vs 服务端文档） | L156 |
| 图校验 | **保存时也校验连通性**（P-09 的静默失败源） | `saveFlow` 中 `validateFlowDocumentGraph` |
| 提交 | 「提交当前任务」= 保存草稿 + git commit | `commitCurrentFlow` |
| 未保存弹窗 | 切换任务/分支时基于 `isDirty` 拦截 | `useOfflineWorkbenchNavigation` |

结论：本次改造**不是从零做自动保存**，而是「把手动保存的调用改为自动触发 + 调整校验与还原点语义 + 删掉过时交互」。

## 3. 目标设计

### 3.1 两层模型

| 层 | 行为 | 用户动作 |
|----|------|---------|
| 草稿（服务端） | **自动保存**：画布编辑防抖 2s 后静默保存；切换任务/分支、页面关闭前强制 flush | 无 |
| 正式版（git） | 「提交」= 当前状态写入 git（填 message，一个动作） | 唯一显式动作 |
| 推送 | 现状不变，独立于提交 | 显式 |

明确移除：

- 工具栏「保存任务」按钮（保留快捷键 Ctrl+S 触发立即 flush 作为肌肉记忆兜底，可选）。
- 「未保存的更改」拦截弹窗——自动保存后「未保存」状态消失；切换任务前强制 flush 即可，不再拦截用户。

### 3.2 「放弃修改」新语义

- 放弃修改 = 回退到**服务端草稿**（最近一次自动保存的结果），即「Revert to Saved」。
- 自动保存模型下，"放弃修改"的触发场景收缩为：用户想撤销**刚做完但还没被自动保存**的几秒操作——价值很低。**建议直接移除该入口**，只保留「回退到上次提交」（git 层操作，红色确认，V2 做版本历史入口时一并设计）。
- V1 过渡：保留「回退到上次提交」语义但改名+红色确认文案（"将丢失自上次提交以来的全部修改"）。

### 3.3 图校验与中间态（关键决策点 D1）

现状保存强制图校验（所有节点连入一张图）。自动保存下这是矛盾的：**编辑中间态天然可能不连通**（用户先摆节点再连线），自动保存若因校验失败而静默不写草稿，等于回到 P-08 的坑。

建议：**草稿保存不做图校验**（草稿允许中间态）；校验收敛到两个动作点：

- 「提交」前校验（连通图 + 数据源完整 + Transfer 映射完整），失败列出问题清单；
- 「执行（debug）」前校验（现状已有部分）。

这同时顺带解开 P-09：并行无连线节点可以保存、可以提交（Kestra 天然支持无依赖并行 task）。是否连「提交」也放行无连线并行，见 D2。

### 3.4 乐观锁与冲突（复用现有）

- 草稿按任务共享，不隔离（数仓场景同时编辑概率极低）。
- 自动保存沿用现有 CAS：冲突时不静默覆盖，复用现有 `saveConflictState` 弹窗，文案改为「XX 的修改已在服务端更新，继续将覆盖」。
- 自动保存冲突后**暂停该任务的自动保存**直到用户裁决，避免后台反复弹窗。
- diff 对比：V2 候选 `@pierre/diffs`（React 组件、本地渲染、含冲突解决 UI；flow.yaml 含明文凭据，**禁用任何公网比对服务**）。

### 3.5 自动保存的失败反馈（决策点 D3）

自动保存失败（网络/冲突以外的错误）不能弹 toast 打断编辑节奏，也不能静默。建议：工具栏常驻一个**保存状态指示**（保存中 / 已保存 HH:mm:ss / 保存失败重试中），用户可点击查看原因。（用户偏好：无「加载中…」式文案，指示用静默/延迟显示风格。）

### 3.6 执行状态回写（P-04 根因）

切换任务弹窗重复出现的直接嫌疑是「执行状态/调度状态回写修改了与草稿脏判定共享的状态」。实现时必须先定位：`hasFlowDraftChanges` 比较的两份文档是否会被执行结果轮询污染。若属实，把执行状态移出草稿文档模型（它本来就不属于草稿内容）。

## 4. 分期计划

| 期 | 内容 | 验收 |
|----|------|------|
| V1 | 自动保存（防抖+强制 flush）；移除保存按钮与未保存弹窗；草稿保存跳过图校验；保存状态指示 | 摆 5 个无连线节点→刷新页面→内容仍在；切换任务无弹窗、无丢失 |
| V1.1 | ~~P-04 根因修复（执行状态与草稿解耦）~~ **已证伪（2026-09-23）**：执行轮询不写草稿、签名不含执行状态；P-04 真实根因是图校验静默拦截保存，V1 已消除 | 无需单独立项 |
| V2 | 「回退到上次提交」改名+危险确认；冲突弹窗文案；可选：撤销/重做（前端内存栈） | — |
| V2.1 | 版本历史（查看/恢复任意提交）；diff 视图（评估 `@pierre/diffs`） | — |

浏览器实测清单（浮层/状态类强制）：编辑后刷新恢复、切换任务无拦截、断网时编辑与恢复、冲突弹窗（两人模拟）。

## 5. 决策点

| # | 问题 | 建议 |
|---|------|------|
| D1 | 草稿保存是否跳过图校验 | **跳过**（草稿允许中间态）；校验收敛到提交/执行前 |
| D2 | 提交是否放行无连线并行节点（P-09） | **放行**（Kestra 支持），连通性仅对「必须有依赖关系」的语义校验，不强制全连通 |
| D3 | 自动保存失败反馈 | 工具栏状态指示，不用 toast 打断 |
| D4 | 「放弃修改」入口 | V1 改名为「回退到上次提交」+ 红色确认；V2 并入版本历史 |
| D5 | 撤销/重做是否进 V1 | **不进**，V2 再做；V1 靠自动保存 + 回退到上次提交兜底 |

## 6. 影响面

- 前端：`useFlowEditingSession`（自动保存调度）、`OfflineWorkbench`（工具栏按钮、导航拦截）、`flowSaveTransaction`（校验拆分）、保存状态指示组件（新）。
- 后端：无改动预期（保存 API 与 CAS 已就绪）；若 D2 放行并行节点，复核提交侧编译是否也有连通性校验。
- 测试：前端单测（防抖/flush/冲突/校验拆分）+ 真实浏览器走查清单（§4）。
